# Registration management in organiser dashboards: participants table, search, filters, saved views, bulk actions, exports, form builder

Scope note: public sources only, no logins. Facts below are documented (cited); anything under "Inferences" is recommendation/judgement. Blocked/unfetched pages are listed under Gaps in each section. Research done 2026-11-18.

## 1. What should the default registrations table, filters and saved views be for a race director, and which per-registrant actions are essential?

### Takeaway
RunSignup is the most complete reference: a default "Active" status filter, ~75 columns behind a column picker, saved reports, and a per-row Edit/Manage menu (edit, transfer, refund, remove). KonfHub (India) and Race Roster add approval/bulk actions and templates; Luma shows a lean guest table with status filters and invalidated-ticket history. None of the public docs describe duplicate detection or a per-participant audit log, so these are differentiators to build.

### Cited Findings
**RunSignup (Participants > View Participants)**
- Column picker: "Customize View" with a "Pick From All Columns" tab listing every field the race has enabled; "Hidden Fields" reveals less-common columns, about 75 in total; an "Edit Registration" column sits at the far right of each row — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Search: one box for Name/Email/Bib Number with an "Exact Match" option for names; sort by Registration Date (default), name or bib — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Filters: Event, Gender, Country, State, Date of Birth, Registered Since/Until, Registration Status, Beginning/Ending Registration ID, Imported (Y/N), Checked In, With Online Payment. Filters apply only after clicking "Update Report" (no live filtering) — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Registration Status values: Active (default), Cleared, Refunded, Deleted, Transferred, Deferred, Transfer to Other Races — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Saved views: "Save Report" and "View Saved Reports" under Report Options; also Summary Info (fees/registrant totals), Graphical Reports, and "View Imports" (review and delete an import) — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Selected columns can be saved as a per-user default, and columns can be renamed/reordered via Custom Columns (per search-result summary of RunSignup University deck and "Custom Columns" post; the underlying pages were not fully read) — [RunSignup University Advanced Reporting (PDF)](https://info.runsignup.com/wp-content/uploads/sites/3/2024/06/Presentation.2024.06.11.RunSignup-University.Advanced-Reporting.pdf)
- Per-row Edit: update personal info (changes the participant's RunSignup account across all races), flag an address undeliverable, change race-specific choices (giveaways, add-ons, bib, question responses), add registration notes. Per-row Manage: view registration, edit info, transfer to another event, edit add-ons, refund, remove — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Check-in is a filterable field ("Checked In"); packet pickup is only mentioned as a use for the Registration ID filter — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- Custom report builder (graph/table/single value) defaults to Active orders; incomplete, deleted and transferred-out orders require changing the filter — [Race Entry blog](https://www.raceentry.com/blog/articles/get-all-the-data-you-need-for-your-race) (note: this page describes Race Entry's own reports; the "Active orders" default is Race Entry's, not RunSignup's)

**Race Roster**
- Participant list pre-fills active participants on open (no need to click "view results"); right-hand collapsible panel selects fields (first/last name, email, sub-event) and display options (date/country formatting); "view results" regenerates — [Race Roster help](https://help.raceroster.com/en-us/knowledge-base/how-to-navigate-race-rosters-updated-participant-list)
- Bib filters: All assigned, Automatically assigned, Manually assigned, Modified bib numbers, Bib unassigned — [Race Roster help](https://help.raceroster.com/en-us/knowledge-base/how-to-navigate-race-rosters-updated-participant-list)
- "Save template" and "Select template" dropdown for reusable report setups; Export button downloads CSV — [Race Roster help](https://help.raceroster.com/en-us/knowledge-base/how-to-navigate-race-rosters-updated-participant-list)
- Help index lists separate articles for: participant search and edit, edit participant info, configuring which fields participants may self-edit, initiate transfer, full/partial refund, make participant inactive (cancel without refund), defer participant, onsite check-in (QR scan, packet pickup, customisable check-in modal), Bib Verification tab — [Race Roster help index](https://help.raceroster.com/en-us/knowledge-base/event-organizers-and-race-directors)
- No Race Roster article title about duplicates appears in the index — [Race Roster help index](https://help.raceroster.com/en-us/knowledge-base/event-organizers-and-race-directors)

**KonfHub (India-based)**
- Table columns: name, email, ticket type, registration date, payment status, ticket delivery status — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Search: full/partial name, email, ticket or order reference number (no phone or bib search documented) — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Filters: ticket type; status (Confirmed, Pending Approval, Waitlisted, Cancelled, Rejected); payment (paid, free, pending, failed); date range — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Per-row: Approve/Reject/Hold (approval flow, Silver plan+), Transfer Ticket (old QR invalidated, new ticket emailed), Cancel Registration with full/partial/no refund (refund 5-10 business days; cancelled tickets cannot be transferred), Edit Details (name, email, phone, custom responses; email change does not resend ticket so "Resend Ticket" is separate) — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Bulk actions via row checkboxes: Bulk Approve, Bulk Cancel, Bulk Resend Tickets, Bulk Forward Invoice; docs recommend filtering before select-all to avoid acting on the wrong group — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Bulk upload CSV/Excel (name+email required, custom columns map to form fields, duplicate-email validation, default 100 rows per batch) — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- "Registration Attempts" tab lists started-but-not-completed registrations with drop-off stage — [KonfHub docs](https://help.konfhub.com/dashboard/participants)

**Luma**
- Search matches first/last/full name, full email or email prefix, and email domain; works with active status filter; sortable by name, email, registration time, check-in time — [Luma help](https://help.luma.com/p/managing-your-guest-list)
- Filters: Going, Invited, Not Going, Checked In, Not Checked In always; Pending and Waitlist appear only when such guests exist; ticket-type filter — [Luma help](https://help.luma.com/p/managing-your-guest-list)
- Bulk Update Status (web only) by CSV upload or pasted emails; for paid events moving to a non-Going status can trigger refund; expanded full-screen guest table supports approve/decline all pending — [Luma help](https://help.luma.com/p/managing-your-guest-list)
- Check-in tracked per ticket (`checked_in_at`), separate from approval status; "Invalidated Tickets" count shown per guest as registration history (ticket replaced, refunded, transferred, declined) — [Luma help](https://help.luma.com/p/managing-your-guest-list)

**Eventbrite**
- Attendee Summary report: up to 8 filters (e.g. event status, payment type, promo code), export Excel/CSV; needs "Basic reports" permission; it, not the Orders report, carries order-form question answers — [Eventbrite help](https://www.eventbrite.dk/help/da/articles/761718/how-to-edit-and-export-an-attendee-summary-report/)
- Check-ins report: filters for order date range, check-in status, include guests; on-screen preview limited to 25 rows, full data via export — [Eventbrite help](https://support.eventbrite.com/hc/it/articles/34865445475602-Download-your-Check-ins-report)

**Active Network (Endurance)**
- Standard download includes First/Last name, email, phones, gender, birth date, age, address, category, and all custom questions; custom registration reports can be limited to a date range and chosen questions; CSV output; export values of question answers cannot be edited in reports — [Active Network support](https://support.activenetwork.com/endurance/articles/en_US/Article/Editing-Export-Values-In-My-Reports-2)

**Playo partner console / Hudle Partner (venue-booking, not race registration)**
- Playo web dashboard: bookings list (who/when/duration, online vs offline, payment status, repeat customers), revenue filters by sport and time period, one-click export, GST-compliant invoices; filters on the bookings list itself are not described — [Playo Partner help](https://playo-partner.freshdesk.com/support/solutions/articles/1070000137391-what-is-the-playo-partner-console-)
- Hudle Partner is described only as an app for managing bookings and growth; no export/filter details found — [App Store listing](https://apps.apple.com/app/id1569130632)

**Performance (general Postgres guidance, not platform docs)**
- GitLab: offset pagination "unsuitable for large database tables"; example page 50,000 read 1,000,000 rows and took ~5.5 s versus ~2 ms for page 1; keyset gives stable performance; ORDER BY must be covered by an index (e.g. `(project_id, id)`); keyset loses page numbers and gets complex with nullable/multi-column ordering; prefer capped counts ("1000+") over exact COUNT(*) — [GitLab pagination guidelines](https://docs.gitlab.com/development/database/pagination_guidelines/index.md)
- Keyset needs a btree index matching columns and sort order; otherwise falls back to a seq scan with filter — [search summary of Postgres keyset articles](https://www.stacksync.com/blog/keyset-cursors-postgres-pagination-fast-accurate-scalable)
- GIN/pg_trgm returns candidate rows that may be rechecked, and cannot provide ordered output — [pgsql-hackers thread](https://www.postgrespro.com/list/thread-id/2650686) (the ordering point is the searcher's inference, not stated in the source)

### Inferences
- Default race-director view (recommendation): Active registrations only, sorted newest first; columns = Bib, Name, Category/Distance, Gender, Age on race day, Mobile, Email, Payment status, Check-in/Kit status, T-shirt size, Reg date. Everything else (blood group, emergency contact, club, ID-proof status, order no., source/coupon) behind a column picker, as RunSignup (~75 hidden fields) and KonfHub (field-select at export) do.
- Default status chips: Active (default), Pending payment, Cancelled/Refunded, Transferred, Deferred, Waitlist — mirrors RunSignup statuses plus KonfHub's payment states. Quick filters: Category, Payment, Checked-in/Kit collected, Bib unassigned, ID-proof pending, Club, plus "custom answer" filter.
- Starter saved views to ship: "Race-week: unpaid", "Bib unassigned", "Kit not collected", "Missing ID proof", "Medical alerts", "Under-18/Masters", "Team/club".
- Essential per-row actions: edit details (with audit), change category (with fee delta), transfer, defer, refund (full/partial), cancel without refund, resend ticket/confirmation, assign/modify bib, mark kit collected/check in, add internal note. Essential bulk: assign bibs, resend, export selection, message, mark collected; require "filter first, show count, confirm" like KonfHub's advice.
- Because RunSignup requires "Update Report" clicks and Eventbrite previews only 25 rows, a live server-side filtered table with keyset pagination would be an improvement; this is a design choice, not a documented competitor feature.
- Supabase/Postgres mapping: keyset on `(created_at, id)` or `(bib_sort, id)` with covering btree index per supported sort (GitLab: each sort needs asc+desc indexes, so limit sort options); use `pg_trgm` GIN indexes on normalised name/email and a generated `phone_digits` (digits only, last-10) column for search; exact match on bib/order number via btree; show capped counts ("10,000+"); keep search as filter on the keyset order rather than ordering by similarity. Add an `event_id` leading column to every index so RLS-scoped organiser queries stay selective. Virtual scrolling in the UI over keyset pages (infinite load) is appropriate at tens of thousands of rows; no platform documents its own row limits (see Gaps).
- Duplicate detection (recommendation, no competitor doc found beyond KonfHub's "duplicate emails" validation on bulk upload): flag same normalised mobile + DOB, or same email + name + event, at registration and in a "Possible duplicates" saved view with merge/cancel actions.
- Activity history (recommendation): per-registration timeline (created, paid, edited field old to new, category change, transfer, refund, check-in, resend) in an append-only table; Luma's "invalidated tickets" and RunSignup's "registration notes" are the closest documented analogues.

### Gaps
- Exact column list of RunSignup's default participant view: not stated; the 2026 RunSignup participant-list blog and reporting-tools blog returned HTTP 403 (blocked), so only the help-centre article was used.
- Duplicate detection and per-participant audit/history: not documented in any fetched page for RunSignup, Race Roster, KonfHub, Eventbrite or Active.
- Wowsly: no public documentation surfaced in search. Hudle/Playo: no registrant-table docs (they are venue-booking consoles). Race Entry: only a blog on reports was read.
- Documented row-count limits or "tens of thousands of rows" performance statements from any platform: none found. Eventbrite's 25-row preview is the only documented limit.
- Active Network Endurance current-generation docs partly unread (Salesforce-hosted support pages).

## 2. What are the best form-builder patterns, and what sport-specific templates should ship?

### Takeaway
Race platforms converge on: a library of simple question types, per-event assignment, parent/child "show for these responses" logic, required/optional flags, drag reorder, hidden/internal questions, and standard (pre-defined) questions. Luma, by contrast, deliberately has no conditional logic or per-ticket questions. No platform documents a "sensitive field" flag or sport templates in the pages read, so those are gaps to fill.

### Cited Findings
- RunSignup question types: Free Form, Check Box, Radio Button/Select Menu, Yes/No, Time Entry, Essay; optional by default, "Require Response" makes mandatory; "Ask for these events" assigns questions per event/category and an unassigned question appears nowhere; "Ask Each Member" repeats the question per group member; reorder by up/down arrows or drag handle; "Internal Questions" hides a question from registrants without deleting; "Standard Questions" are predefined and RunSignup pre-fills answers from other races; supports image and "Additional Details" help text; no preview described — [RunSignup help: Add Registration Questions](https://help.runsignup.com/support/solutions/articles/17000062846-add-registration-questions)
- RunSignup question logic: Race > Registration > Questions > "Question Logic"; choose a parent question and tick "Show For These Responses"; dependent must come after its parent in order; questions not marked "Ask Each Registrant" cannot depend on ones that are; parent "(No Parent Question)" means always shown — [RunSignup help: Setup Question Logic](https://help.runsignup.com/support/solutions/articles/17000062847-setup-question-logic)
- RunSignup supports hiding standard questions, a "Secure Information Option" (listed as a blog title in the information-collection category; content not read), and setting custom questions via API — [RunSignup info blog search results](https://info.runsignup.com/category/key-features/information-collection/page/2)
- Race Roster: has "How to Create a Custom Registration Question" and "How to create a hidden/internal question", plus a release letting participants create options for custom questions — [Race Roster help index](https://help.raceroster.com/en-us/knowledge-base/event-organizers-and-race-directors); [Race Roster release](https://raceroster.com/major-releases/new-release-participants-can-create-options-for-custom-questions)
- Luma question types: Text (short/long), Options (single/multiple), Social Profile, Company, Checkbox, Terms, Website; required toggle; Name and Email cannot be turned off (locked core); split first/last name needs Luma Plus; phone is optional toggle; no conditional logic; no per-ticket questions; reorder not documented — [Luma help: Collect Registration Questions](https://help.luma.com/p/collect-registration-questions)
- Luma: deleting a question keeps old answers on guest record but drops the column from CSV exports — [Luma help: Download Guest CSV](https://help.luma.com/p/download-guest-csv)
- Active Network: team members (incl. captain) get a separate question set configured apart from standard form questions; custom questions flow into the registration report as columns — [Active Network support](https://support.activenetwork.com/endurance/articles/en_US/Article/Internal-New-Form-Questions-Adding-Additional-Team-Member-Questions)
- Active Network also has a "Custom Question Conditional Display" article (camps product; found in search listing only, not read) — [Active Network camps support](https://support.activenetwork.com/camps/articles/en_US/Article/Custom-Question-Conditional-Display)
- KonfHub: edits and bulk-upload column mapping reference "custom form responses"; no dedicated form-builder page was read — [KonfHub docs](https://help.konfhub.com/dashboard/participants)

### Inferences
- Recommended builder patterns: (a) locked core block (name, DOB, gender, mobile, email, category) that organisers cannot delete but can reorder within limits; (b) question library with types: short text, long text, single select, multi select, yes/no, number, date, file upload (ID proof), consent checkbox, phone (any format), dropdown with "other"; (c) per-question scope: all / specific categories / group member; (d) simple one-level "show if parent = X" logic (RunSignup's model is deliberately one parent, ordered) with validation that blocks cycles and ordering errors; (e) required/optional, help text, image; (f) sensitivity flag (public/organiser/restricted) controlling column visibility, export inclusion and masking; (g) drag reorder, live preview as mobile and desktop, "hide, don't delete" so history is preserved (RunSignup Internal Questions; Luma's column loss on delete is a pitfall); (h) answer-option values locked after first registration (Active cannot edit export values).
- Sport templates to ship (recommendation): Running/Marathon (T-shirt size, blood group, emergency contact name+phone, medical conditions, expected finish time/pace, club, previous events, ID proof for age-restricted/elite, bib name, kit collection by proxy); Cycling (bike type, helmet acknowledgement, jersey size, club); Triathlon (swim proficiency, wetsuit, bike/race licence); Trail/Ultra (mandatory gear acknowledgement, qualifying race proof, medical fitness declaration); Walkathon/Kids (guardian consent, age band, group/school); Swimathon (stroke, seed time). Common India items: blood group, emergency contact, club, T-shirt size, ID proof (Aadhaar/PAN/passport/school ID, store file privately; avoid collecting full Aadhaar number), age computed on event day, gender options beyond binary with categories mapped separately from stated gender, mobile in any format normalised to E.164 with +91 default, WhatsApp consent.
- Sensitive-field flags are worth building because none of the fetched docs describe one (RunSignup "Secure Information Option" blog exists but was unread).

### Gaps
- RunSignup "Secure Information Option" and "Sub Questions" blog content not read; Race Roster custom-question articles and Eventbrite order-form question docs not read (fetch limits / 404 on Eventbrite article).
- No documented preview feature in RunSignup's question docs; Luma reorder unknown.
- No sport-specific form templates found on any platform in public docs read.
- KonfHub and Wowsly form-builder docs not located (KonfHub llms.txt index exists at help.konfhub.com/llms.txt but was not fetched).

## 3. Which exports do organisers need on race week, and how are sensitive fields protected in exports?

### Takeaway
Documented exports centre on CSV/Excel of the filtered participant list with chosen columns; RunSignup additionally offers Google Sheets, PDF, Hy-Tek and Webscorer scoring exports, Dropbox and a bib labels builder; KonfHub offers field-selectable XLSX/CSV with QR codes. No platform page read documents field-level protection of sensitive columns in exports, so that is an open design area.

### Cited Findings
- RunSignup Export Options: Daily Registration Summary, Customize Export (controls add-on layout), CSV (all columns or filtered view), Google Sheets, PDF, Hy-Tek and Webscorer.com scoring exports, Dropbox, Bib Labels builder — [RunSignup help](https://help.runsignup.com/support/solutions/articles/17000063214)
- RunSignup has a "Participant Report Export to Email" feature (title only in search results) — [RunSignup info](https://info.runsignup.com/?p=1909)
- RunSignup timing integrations (not file exports): Agee Race Timing, Laurel Timing, RaceDay Scoring, Race Result, RunScore, The Race Director, ChronoTrack, plus REST API and webhooks — [Race Entry blog / report listing page](https://www.raceentry.com/blog/articles/get-all-the-data-you-need-for-your-race) (this page is Race Entry's; the integration list belongs to Race Entry, not RunSignup. RunSignup integration list not independently verified)
- Race Entry pre-built reports include Registration Question Stats (e.g. shirt sizes), registration heat map by zip, retention, revenue by category; question stats downloadable — [Race Entry blog](https://www.raceentry.com/blog/articles/get-all-the-data-you-need-for-your-race)
- KonfHub download: apply filters, select fields (name, email, ticket type, form responses, QR code image URL, ticket PDF URL, invoice URL), choose QR embedded or linked, XLSX or CSV; docs suggest downloading a day before the event as an offline backup for check-in/badge printing — [KonfHub docs](https://help.konfhub.com/dashboard/participants)
- Luma CSV export: respects filters/search, includes coupon code, custom source, one column per registration question, one row per ticket in group registrations — [Luma help](https://help.luma.com/p/download-guest-csv)
- Eventbrite: Attendee Summary export to CSV/Excel gated by "Basic reports" permission, i.e. role-based access to the report — [Eventbrite help](https://www.eventbrite.dk/help/da/articles/761718/how-to-edit-and-export-an-attendee-summary-report/)
- Active Network: CSV opens in browser; custom registration reports can be restricted to chosen questions and an empty template keeps only headers — [Active Network support](https://support.activenetwork.com/endurance/articles/en_US/Article/Editing-Export-Values-In-My-Reports-2)
- Race Roster: Export to CSV, saved templates; hidden/internal questions exist for organiser-only data — [Race Roster help](https://help.raceroster.com/en-us/knowledge-base/how-to-navigate-race-rosters-updated-participant-list)

### Inferences
- Race-week export set (recommendation): (1) Master list CSV/XLSX; (2) Packet-pickup list: bib, name, category, T-shirt size, kit status, signature column, sorted by bib/name, PDF printable; (3) Bib label/number-card file; (4) Timing file: bib, name, gender, DOB/age category, distance, club, chip ID/wave in the timer's format (Hy-Tek/Webscorer-style as RunSignup offers, or CSV for RaceResult/Chronotrack-style tools); (5) Emergency/medical sheet: bib, name, blood group, emergency contact, medical conditions, restricted to medical team; (6) T-shirt/size summary for vendor; (7) Unpaid/pending list; (8) Category/age-on-race-day counts; (9) Check-in/no-show list post-event. Pre-generated offline copy a day before (KonfHub advice) matters for poor connectivity at venues.
- Sensitive-field protection (recommendation): per-field sensitivity tag; export requires explicit role permission (Eventbrite-style role gate); sensitive columns excluded by default and need a re-confirmation or reason; export audit log (who, when, filters, columns); watermark/time-limited signed download links from Supabase Storage rather than emailing files; mask phone/ID in on-screen table by default; ID-proof files in private bucket with signed URLs; emergency sheet generated as a purpose-bound template instead of ad hoc column selection; retention/auto-delete after the event to align with India's DPDP Act obligations (verify current rules before relying on this).
- Excel pitfalls to handle: mobile numbers as text (leading + and zeros), UTF-8 BOM for Indic names, formula-injection escaping for cells starting with =,+,-,@.

### Gaps
- No public documentation found on how any platform restricts or masks sensitive fields in exports; RunSignup's "Secure Information Option" article not read.
- No platform page read describes a dedicated packet-pickup list or medical/emergency export template (RunSignup mentions only bib labels and Registration ID filter use); possibly in blocked RunSignup 2026 blogs (HTTP 403) and RunSignup University PDFs (not fetched).
- Timing-file formats for Indian timers (e.g. RaceResult, Chronotrack, local chip timers) not researched.
- Wowsly, Hudle: no exports documented publicly in sources found; Playo only states "one-click export" and GST invoices for bookings revenue.
- India-specific requirements (DPDP Act, ID-proof norms for events) are not sourced here and need separate legal verification.
